## Integration Findings

### CRITICAL: PROP-06 — PropArbitrageAgent EV Against Wrong Market

`prop_arbitrage_agent` (`prop/arbitrage.py` lines 155–169) reads `context_signals.odds_snapshot` for implied probability. This is the **h2h game-winner moneyline market**. Player prop odds are ingested separately into `player_prop_snapshots` via `write_player_prop_snapshot` but are **never read** for EV computation.

**Effect:** EV calculation compares `PropResult.true_probability` (e.g., P(player passes for >250 yards)) against P(team wins). These are incommensurable quantities. EV signals and Kelly sizing for all props are mathematically invalid.

**Fix:** `prop_arbitrage_agent` must read `state.get("player_prop_snapshots")`, match on player/market/line, and derive implied probability from the prop snapshot's American odds field.

### DOCUMENTATION: ARBT-01 — Quant → Arbitrage Two-Invocation Pattern Undocumented

No direct graph edge `quant_agent → arbitrage_agent`. The two-invocation checkpoint pattern works correctly via SqliteSaver but is undocumented. Callers invoking `"arbitrage_analysis"` without a prior `"quant_analysis"` in the same `thread_id` receive a silent `{"ev_signal": None, "error": "quant_result missing or invalid"}`.

### DOCUMENTATION: CTXT-04/PROP-04 — Teammate-Out Signal Dependency Undocumented

`situational_params` (teammate_out signals) are only present in prop agent state when a prior `"context_update"` invocation ran in the same thread. Prop agents silently fall back to `None`. Functional but requires undocumented caller knowledge of invocation ordering.
