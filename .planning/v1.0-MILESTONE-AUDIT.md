## Critical Gaps

### Gap 1: QUANT-03 — context_agent write-path for stat_type absent (MEDIUM)

**What was fixed (quick-1):** `GraphState.stat_type: str | None` added at state.py:161. `make_quant_agent` now reads `state.get("stat_type") or "passing"` — rushing/receiving templates are structurally reachable.

**What remains:** `context_agent()` return dict at agents.py:364-368 never includes `stat_type`. The field is read correctly by `make_quant_agent` but the context pipeline never auto-populates it from injury signals or market context. Callers must inject `stat_type` into the initial `graph.ainvoke()` call manually.

**Effect:** Rushing and receiving query templates are available to API callers who know to set the field, but the documented automatic routing behavior (context_agent detects non-passing market → writes stat_type → quant_agent picks correct template) is not implemented.

**Fix:** In `context_agent()` return statement, infer `stat_type` from `context_signals` or `state.get("prop_filters")` / `state.get("request_type")` and include it in the returned dict.

---

### Gap 2: PROP-06 — NFL receiving prop alias key mismatch (HIGH)

**Requirement:** "PropArbitrageAgent flags mispriced player props by comparing PropResult.true_probability against sportsbook implied probability"

**What's broken:** `_PROP_TYPE_ALIAS_MAP["rec_yds"] = "player_receiving_yards"` at `prop/arbitrage.py:46`, but `NFL_PROP_MARKETS` at `ingestion/odds_poller.py:37` uses `"player_reception_yds"`. The `PlayerPropSnapshotCreate.prop_type` stored in the database is `"player_reception_yds"`. The alias map lookup for `"rec_yds"` → `"player_receiving_yards"` never matches any stored snapshot.

**Effect:** For NFL receiving yard props, `matched_snapshot` is always `None`. `prop_arbitrage_agent` falls back to `context_signals.odds_snapshot` (h2h moneyline implied probability) for EV comparison — a mathematically incommensurable comparison. Phase 23's fix is negated for the receiving yards market.

**Fix:** Change `_PROP_TYPE_ALIAS_MAP["rec_yds"]` from `"player_receiving_yards"` to `"player_reception_yds"` to match what `odds_poller.py` stores.
